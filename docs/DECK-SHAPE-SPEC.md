# Deck Shape Spec

> **Purpose:** A machine-readable map of the *best data shape* for every slide in every
> registered deck. Feed this to an LLM when generating or rewriting deck content so it
> emits the exact field structure each slide's layout expects.
>
> **Scope:** 6 registered decks (those in `content-registry.ts`). 35 slides total.
> (`atelier-sage` + `signal-cobalt` — 9 sample slides — were removed; see §3.)
> Generated by analyzing each deck's `structure.js` (layout per slide) against its
> `content.json` (actual populated fields + array cardinality) and the
> `content-types.ts` contracts.
>
> **How to read a shape line:** `field (size)` = scalar text; `N items{subfields}` = array
> of N objects with those subfields; `?` = optional; `→` = paired relationship.
> Counts are the *current* cardinality and serve as the recommended target.

## 3. Duplicate-shape report (trim candidates)

**Status: RESOLVED & EXECUTED — `atelier-sage` + `signal-cobalt` removed; no content of the 6 real decks touched.**

> ✅ **Resolution (executed):** Reading the content confirmed the flagged "duplicates"
> are **shape-twins, not content-duplicates** — every slide in the real decks carries
> unique material, so deleting them would lose content with no dedup benefit. A layout
> system reusing shapes is correct by design. The only true redundancy was structural:
> `atelier-sage` and `signal-cobalt` were **unplanned theme samples** (`brandLine:
> "Reference Study"`, "Sample Slides", "inspired by deck.gallery") that added **zero
> unique shapes**. **Action taken: both decks removed** — un-registered from
> `content-registry.ts`, dropped from `App.v14.tsx`'s `DECKS` map, and their content
> folders + the `reference-decks/` re-export wrapper deleted. Their same-named *themes*
> in `tokens/themes.ts` were kept (selectable styles, deck-independent). Verified:
> typecheck clean, 93/93 tests pass, production build succeeds.
> `eng-architecture`/`eng-code-flow` merge: deferred.
